# 0006 · 语音入口 v2：固定槽位、可见退路、可撤销

- 日期：2026-11-25
- 状态：已采纳并实现
- 依据：`design-lab/research/C-voice-entry.md`（858 行 / 21 个来源 / A-B 混合）；M3 48dp 交互目标；WCAG 2.5.1（path-based gesture 需单指针替代）
- 修订：**部分推翻 0005 §4** 的「空输入麦克风 / 有文字发送」互换

## 1. 触发

0005 定稿时 C 研究未回，按 Apple 听写 + 微信两条 A 级证据选了点按 + 长按加速器，并让麦克风与发送键**互换槽位**（空输入显示麦克风，有文字显示发送）。C 返回后指出三个问题：

1. 「互换」没有官方规则依据，且**有文字时语音入口消失**，与「常驻」目标直接矛盾；微信的语音键是模式切换键，不占发送位（C §4.1-1）。
2. 主流模型是「点按/停止 → 确认后发送」；松手即发只见于语音消息/对讲场景（C §4.1-2）。
3. 「上滑取消」是 B 级产品惯例，不是标准；WCAG 2.5.1 要求 path-based gesture 有非路径替代，而长按录音态当时只有文字、没有可见按钮（C §4.1-3）。

另外两条与实现直接相关：转写结果不自动发送是对的，但缺**显式撤销/重试**；麦克风应 ≥48×48dp 并与发送键留间距，不能靠难达位置防误触。

## 2. 原文

C 报告 §4.2 推荐形态（逐字）：

```
空输入：  [ + ] [ 输入框 .................... ] [ 🎤 48 ]
有文字：  [ + ] [ 输入框 ................ ] [ 🎤 48 ] [ 发送 48 ]
```

> 「麦克风固定在输入框右侧，**发送键出现/消失时麦克风不位移**；空间不足时宁可压缩输入框，也不要让麦克风跳到发送键的位置。」

C §4.3：

> 「录音态必须有可见的 X 和停止按钮；上滑 56pt 只是快捷方式，不能替代按钮。」
> 「显示计时和上限（建议 60 秒，参考微信 S1）；到达上限时自动停止并转写，不要静默丢弃。」

C §4.4：

> 「在输入框上方显示一条短暂提示：『已转写 · 撤销』，保留 5 秒；点『撤销』恢复转写前的文本。」

C §4.1-5：

> 「麦克风至少 48×48dp，和发送键留出间距；误触靠尺寸/间距/撤销，不靠把按钮挪到难达的角落。」

## 3. 判断

**保留 0005 的交互模型（点按为主 + 未聚焦长按加速器），改布局与退路。**

| 问题 | 0005 | 0006 |
|---|---|---|
| 麦克风位置 | 与发送键互换 | 固定在输入框右侧，永远可见 |
| 发送键 | 占据麦克风的位置 | 独立槽位，空输入时透明占位、不可点 |
| 尺寸 | 44×44 | 48×48（Material 3 交互目标） |
| 录音态 | 点按态有取消/停止；长按态只有文案 | 两态共用「取消 + 计时 + 停止」 |
| 上限 | 无 | 60 秒自动停止并转写 |
| 转写后 | 填入输入框 | 填入 + 5 秒「已转写 · 撤销」 |
| 失败 | SnackBar 报错 | 报错 + 有音频时「重试」；空结果提示「没听清」 |

为什么不用「有文字时把麦克风移到左边」：那会改变麦克风位置，等于换个方式违反「常驻入口不位移」；为什么不让发送键贴最右、麦克风在其左：C 的推荐形态是 `[🎤][发送]`，发送在最右符合右手拇指习惯，也符合我们已有的发送位置。

为什么空输入时要留发送槽位（视觉上一段空白）：这是「麦克风不位移」的代价。用 48dp 的固定槽位，换来的是「用户打字时麦克风不会跳走」。这个空白在深色上看不出来，在浅色上是一段无内容区；比按钮跳动便宜。

## 4. 实现

`apps/mobile_flutter/lib/features/chat/widgets/composer.dart`：

- `_MicButton` 48×48；新增 `emphasized`：空输入时品牌实心，有文字时透明底 + `border` 描边 + `textSecondary` 图标（让位给发送键，但不消失）。
- 发送键改为常驻槽位：`IgnorePointer(ignoring: _empty)` + `AnimatedOpacity(opacity: _empty ? 0 : 1)`，尺寸 48×48；图标 22。
- 录音态：`_ticker` 每秒 +1，`_seconds` 显示为 `0:07`；到 `_maxSeconds = 60` 自动 `_finishRecording(cancel: false)` 并触发中震。
- `_VoiceBar` 两态统一：红点 + 「正在录音」/「正在录音 · 上滑取消」/「松开取消」+ 计时 + 「取消录音」(×) + 「停止录音」(■)，按钮均 48×48 带 tooltip。
- 长按态点「停止/取消」与松手共用 `_finishHold`，进入前加 `if (!_holding) return;` 防止松手二次结算。
- 焦点守卫与「手势只挂 TextField」保持 0004 不变。

`apps/mobile_flutter/lib/features/chat/presentation/chat_screen.dart`：

- `_fillFromVoice` 记录 `previous = _controller.value`，写入后 SnackBar「已转写」+「撤销」5 秒。
- `_finishVoice` / `_transcribe` 拆开：转写失败且有音频路径时，SnackBar 带「重试」；空文本提示「没听清，请再说一次」，不写进输入框。

## 6. 没做

- 试听/续录/删除的「语音消息」面板：Dream 只做转写，语音不是消息类型（C §4.4）。
- 设置里的「语音输入开关 / 长按录音开关」：C 建议保留，但属于设置页改造，留给后续。
- 首次一次性提示「点按说话」：与 0004/0005 的「长按输入框」提示合并设计，避免两条提示打架（C §4.5 提到，暂缓）。
- 录音上限的进度环/倒计时视觉：当前只显示 `0:07` 文本；60 秒自动停止已有提示音+震动，但**没有可见的倒计时警示**（05 秒剩余）。记为已知缺口。

## 7. 失效条件

- 若产品决定「语音消息」成为一等消息类型，§4 的转写模型与 §6 的面板都要重开。
- 若未来上平板/桌面，48dp 与键盘焦点、鼠标 hover 需要重新审计（C 只覆盖触屏）。
- 若 60 秒上限与后端 ASR 超时/费用模型冲突，改上限需同步改 `VoiceController`。
