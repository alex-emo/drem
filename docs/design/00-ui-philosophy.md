# 00 · UI 哲学：Quiet Instrument

## 1. 案例研究

### Things 3（iOS）

来源：[Things 3 设计系统拆解](https://github.com/feimacode/open-design-agent-kit/blob/f99b3caeb91b7410d54610f3a2e41744adfccff7/packages/content/assets/open-design/design-systems/things-3-ios/DESIGN.md)

- 纯白画布 + 极大留白，**“平静就是产品”**；层级靠字号、字重和留白，不靠卡片堆叠。
- 单一强调色（Things Blue）只用于选择、主动作、完成态；另一个暖色只标记“今天”。
- 发丝级分割线、几乎无阴影；唯一的阴影留给创建按钮。
- 44pt 触控目标、4pt 基线、20pt 页边距；动效短（180–300ms）、有触感、可预期。
- 启示：**克制不是少做，而是每个像素都有理由**；强调色越少，越有指向性。

### Linear

来源：[Why is quality so rare?](https://linear.app/now/why-is-quality-so-rare)、[A Linear spin on Liquid Glass](https://linear.app/now/linear-liquid-glass)

- 质量是策略：小团队、端到端负责、零 bug 政策、内部先用 MVP。
- 触感来自细节：按压轻微抬起、越界轻微形变、滚动边缘的渐强模糊。
- 不直接套用系统材质，而是从品牌与工作流出发重做；**形式服务于专注，不是炫技**。
- 启示：**动效是反馈，不是装饰**；每个交互都要有“按下去是真的”的手感。

### AI 助手界面结构研究

来源：[Dissecting the Assistant User Interface](https://eug.github.io/posts/dissecting-the-assistant-user-interface.html)

- 主流助手收敛为三段式：**header（系统/身份/模式）→ content（空态即指令）→ input（真正的权力面）**。
- 空态不是装饰，是第一次教学：建议卡在塑造用户对产品的预期。
- 输入区暴露多少能力，决定了产品被当成“聊天框”还是“工作台”；渐进披露优于堆开关。
- 临时会话/隐私入口是信任基础设施；header 是“契约区”。
- 启示：**空态要教一件事，输入区要只暴露当下需要的能力**；我们不做“工具带”，做安静的合作者。

### Claude 设计指南

来源：[Claude MCP Apps design guidelines](https://claude.com/docs/connectors/building/mcp-apps/design-guidelines)

- 原生感：继承宿主 token、字体、圆角；不硬编码颜色。
- 移动端：44pt 目标、安全区、全宽布局、无嵌套滚动；骨架屏优于转圈。
- 三档字号（heading/body/caption）+ 两个字重即可建立层级。
- 优先可见控件，少用隐藏菜单；复杂交互渐进披露。
- 启示：**移动端先解决可达性与可读性，再谈风格**。

## 2. 综合：我们自己的命题

Dream 不是“另一个 DeepSeek 皮肤”，也不是工具带。它应该像：

> 一张安静的纸，一支随时能写的笔，和一个不会抢话的协作者。

### 六条原则

1. **内容优先**：屏幕上最先被看见的应该是用户的问题和 Dream 的回答，不是 chrome。
2. **单一强调**：品牌蓝只标记主动作、焦点、选择、流式光标；其余用中性色。
3. **结构线而非卡片**：用 1px 线、留白、字号建立层级；不堆阴影和圆角卡片。
4. **输入是权力面**：输入区只放“现在能用”的能力；未接入的能力明确标注，不做假按钮。
5. **细节即质量**：按压、聚焦、键盘弹起、滚动边缘、错误恢复都要有确定反馈。
6. **可读的状态**：空态、流式、停止、错误、离线、减少动效，都要有明确且不吓人的表达。

### 产品人格

- 安静的合作者：不主动卖功能、不堆建议、不模拟情绪。
- 可信的工具：状态可见、错误可恢复、隐私边界清楚。
- 有编辑感：左对齐、编号、细线、克制的字距；不是仪表盘。

## 3. 借什么，拒什么

借：

- Things 3 的留白、单强调色、发丝线、44pt、短而动因明确的动效。
- Linear 的工艺标准、按压手感、边缘细节、对“半成品”的拒绝。
- 助手研究的三段式结构、空态教学、渐进披露、临时会话的信任价值。
- Claude 指南的原生感、三档字号、安全区、骨架屏。

拒：

- 逐像素复刻 web / DeepSeek 的居中双列卡片与胶囊输入。
- 大面积玻璃拟态、彩色渐变卡片、装饰性阴影。
- 把未实现的能力做成可点击的假按钮。
- 为了“显高级”而放慢动效、加无意义过场。
- 用全局字符串替换处理身份/厂商问题（历史教训）。

## 4. 体验指标

P0 可测：

- 冷启动到首帧 < 1.5s（中端 Android）
- 点击到视觉反馈 < 100ms
- 页面切换 280ms；按压 120ms；气泡 260ms
- 60fps 稳定；120Hz 设备不掉帧（滚动/输入）
- 键盘弹起无布局跳动；输入框始终可见
- 减少动效开启时，所有位移/缩放为 0，内容不丢失
- 所有可点击目标 ≥ 44×44pt；深/浅色对比度 ≥ 4.5:1（正文）

P1 增加：

- 首字 < 100ms（服务端 SSE 到达后）
- 流式追加不引起整列重排
- 停止后本地状态与界面一致

## 5. 反模式清单

- 空态超过 4 个建议；建议文案写成营销口号。
- 输入框下方堆一排模式开关。
- 消息气泡五颜六色、圆角不一致。
- 页面切换从四个方向飞入；列表项逐条弹跳。
- 错误只显示“出错了”，没有下一步。
- 用 `withOpacity` 叠出灰蒙蒙的层级；用纯黑/纯白硬碰。
- 在 feature 里写 `Color(0x...)` 或 `Duration(milliseconds: 300)`。

## 6. 决策记录

- 2026-11-25：确定“Quiet Instrument”；放弃 DeepSeek 式居中空态，改为左对齐编辑式空态 + 编号建议。
- 2026-11-25：品牌蓝保留 `#5686FE`，但表面色改为更中性的 Flutter 自有色板。
- 2026-11-25：P0 不做假发送；发送按钮未接入时只给明确 P1 提示。
