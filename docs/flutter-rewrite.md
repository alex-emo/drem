# Flutter 移动端重构 · 分支章程

- 状态：草案 v0.1（2026-11-24）
- 分支：`feat/flutter-mobile-rewrite`
- 范围：`apps/mobile` 的 iOS / Android 客户端；`apps/server`、`apps/web` 首期不改。
- 原则：功能对等后切换，旧 Capacitor 壳保留为回退路径。

## 1. 目标

用 Flutter 单代码库重写 iOS / Android 客户端，替换 Capacitor WebView 壳；保留现有 `/api/v1`、SSE、云备份信封与账号体系。首期不改服务端协议，不改变用户数据归属。

## 2. 体验基线（验收硬指标）

### 2.1 简洁

- 一屏一个主动作，低频操作收进菜单 / 底部 sheet。
- 默认不展示调试信息、版本号、内部错误码；错误只给「人话 + 请求编号」。
- 去掉无目的的装饰性分割线、阴影、渐变；用留白和字重建立层级。

### 2.2 现代

- Android 用 Material 3，iOS 用 Cupertino 自适应组件；不强行两端同一套控件。
- 深色优先，浅色同等完成度；跟随系统主题，支持手动切换。
- 尊重安全区、动态字体、横屏、折叠屏；触控目标 ≥44×44。

### 2.3 优雅

- 8pt 网格；字号、圆角、间距、动效时长全部 token 化，禁止散落魔法数。
- 内容先行：消息区最大宽度受控，代码块 / 表格 / 公式不溢出。
- 图标线性统一，插画克制；空态、加载态、错误态三态齐全。

### 2.4 高效

- 冷启动 < 1.5s，热启动 < 500ms（中端真机，不含网络）。
- 输入到首字上屏 < 100ms；流式增量渲染不整页重建。
- 列表 1 万条消息可滚动；首屏只构建可见区域。
- 所有网络请求可取消；停止生成先本地结算，再断流。

### 2.5 流畅

- 目标 60fps；120Hz 设备跟随 120fps；滚动掉帧率 < 1%。
- 禁止在 build / 滚动回调里做 JSON、加密、Markdown 解析。
- 图片、代码高亮、公式异步解码；占位尺寸稳定，避免布局跳动。
- 键盘弹起 / 收起与输入框、列表联动，无闪跳。

### 2.6 动效

- 时长：微交互 120–180ms，容器展开 220–280ms，页面转场 280–320ms。
- 曲线：标准 `cubic-bezier(0.2, 0, 0, 1)`；退出略快于进入。
- 手势 1:1 跟手（侧滑返回、下拉关闭、拖拽），松手用 spring 收敛，不硬切。
- 列表增删用 `AnimatedList` / `SliverAnimatedList`；消息流式更新只重绘变化节点。
- 支持「减少动效」系统开关；动效服务于状态变化，不做纯装饰循环动画。

## 3. 技术基线

- Flutter stable（版本待定，需团队确认）+ Dart 3；单代码库自适应双端。
- 架构：feature-first；presentation / domain / data 分层；状态管理、路由、DB、代码生成待选型，不在本章程内锁定。
- 网络：复用 `/api/v1` 与 SSE 事件（`start` / `thinking` / `delta` / `sources` / `refusal` / `done` / `error`）；保留 413 裁剪重试、停止语义、错误码映射。
- 本地：加密数据库；信封兼容 `dream1.<iv>.<b64>`、`dream-export`、`dream-backup v2`；迁移不得静默清空。
- 渲染：Markdown、GFM 表格、KaTeX、代码高亮、引用卡片、分支版本切换。
- 原生能力：录音 + WebSocket ASR、TTS、文件选择、分享、深链、安全区、键盘、APK 安装 / iOS 更新提示。
- 可观测：启动、卡顿、崩溃埋点；不上报聊天正文、token、密钥。

## 4. 迁移策略

1. 并行：旧 Capacitor 应用继续维护；Flutter 版内部 dogfood。
2. 数据：首启动检测旧版本地数据 → 导出 / 导入桥接；云备份保持兼容；失败必须可见。
3. 切换：功能矩阵全绿 + 灰度 + 可回退，才替换默认客户端。
4. 版本：与 `apps/server/src/config.ts` 的 `appVersion` / `appVersionCode` 对齐；不做双写。

## 5. 阶段

- P0：设计 token、导航骨架、主题、错误/空态、CI 与真机调试链路。
- P1：登录、会话列表、聊天 SSE、本地库、分支树、停止/重试。
- P2：文件、搜索、语音、导入导出、云备份、设置。
- P3：反馈、更新、iOS 签名、性能与动效打磨。
- P4：功能对等验收、数据迁移、灰度、发布。

## 6. 分支与协作

- 从 `feat/flutter-mobile-rewrite` 切 `feat/flutter-*`；PR 回到本分支；`master` 不动。
- 本分支默认不部署；发布必须得到明确指令。
- 提交格式 `type(scope): summary`；一个 commit 只做一件事。
- 代码目录暂定 `apps/mobile_flutter/`；在切换完成前不覆盖 `apps/mobile`。

## 7. 待决策

- 状态管理（Riverpod / Bloc / 原生）、路由（go_router / auto_route）。
- 本地库（Drift / Isar / SQLCipher）与加密方案。
- Markdown / 公式 / 代码高亮 / 音频 / SSE 的库选型。
- 是否抽出共享 Dart 包；是否保留 Web 端独立演进。
- APK 自更新方案、iOS 分发方式（TestFlight / 企业签 / App Store）。

## 8. 风险

- 现有功能面大：语音、搜索、四种导入、云备份、分支编辑、管理入口。
- 双端并行期维护成本；数据迁移与加密兼容是最高风险项。
- Flutter 自更新、后台下载、安装权限在 Android 各厂商差异大。
- 不复制现有缺陷：移动端 `SYSTEM_PROMPT` 的 DeepSeek 身份、Mermaid 假功能、tombstone 复活窗口。

## 9. 验收

- 功能矩阵逐项通过；性能预算达标；动效 checklist 通过。
- 真机矩阵：Android 10 / 13 / 15，iOS 16 / 18；含小屏、折叠屏、120Hz。
- 无 P0 / P1 缺陷；数据迁移可回滚；旧客户端可继续登录使用。

## 10. 视觉方向调整（2026-11-24）

不做 web / DeepSeek 的逐像素复刻。功能矩阵、接口、数据语义保持一一对应，视觉与交互由 Flutter 端重新设计：

- **布局**：不使用“居中大标题 + 双列建议卡 + 底部胶囊输入”的 DeepSeek 空态；改为左对齐编辑式标题、编号建议列表、通栏细线输入区。
- **色彩**：品牌蓝只作强调；底色比 web 更暗、更中性，用户气泡用低饱和蓝灰，助手消息不套气泡。
- **层级**：用字号、字重、留白和 1px 结构线，不堆叠卡片与阴影；渐变只用于极轻的环境光。
- **动效**：页面淡入 + 轻微位移，气泡淡入 + 6px 上移；全部遵循系统“减少动效”。
- **约束**：不为了“像 DeepSeek”而加入假功能、假模型名、假状态；未接入的能力明确显示为 P1。
